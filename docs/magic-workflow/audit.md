# Magic workflow audit — before expansion

## Architecture and behavior

- MagicLabController renders schema-driven choices; SpellSpec owns validation and estimates; MagicService and executor registries own combat. Nine stable MagicLabSlot identities preserve cooldown behavior.
- MagicLibraryProfile v1 stores Version and Slots under EnfleshedMagicLabLibraryV1, key u:<user id>. Colors serialize as RGB arrays. Load hydrates Development only on the server; Apply validates, equips, debounces persistence. Failed/malformed reads are not overwritten.
- Drafts are client session state per slot. P currently returns to Slots; footer Save equips, Save + cast equips then casts. No independent collection, search, favorites, archive, import/export or preview management controls exist.
- Existing Tags inside a spell are validated spell identity data; new organizational labels must live outside the definition.
- Incompatible Principle/Form and payload/event combinations are real engine restrictions. Disabled recursive-condition operations enforce node/depth limits. No placeholder duplicate/delete/import buttons exist to complete. Generic not-implemented copy is misleading and will be replaced with compatibility explanations.
- TrainingDummyService creates owned stationary tagged Humanoids with health labels, reset on death, restore/clear commands and spawn limits. These use real damage/targeting. Anchored dummies are not representative of displacement on unanchored characters.
- SandboxService builds the lower-layer city; OpeningService anchors the player until appearance/starter selection. ActionRouter requires OpeningComplete. City, assignments, population and world events start by default.
- Other persistence: discovery v3 with v1/v2 migrations, Locus profile, persistent constructs, equipment. Leave these schemas and narrative systems intact.

## Controls and dynamic states

See ../magic-grimoire-redesign.md for the original control and workflow inventory. Setup contains Form, name/tags, Principle/Expression/Element, casting, optional Locus/resource/environment restrictions, lifetime and geometry. Targeting contains aim modes, relationships, range, consent and recursive conditions. Effects contains timing, compatible payload settings, behaviors and motion phases. Presentation contains visuals/audio and local debug geometry. Test contains casting, consent and four dummy actions. All dependent sections remain available.
