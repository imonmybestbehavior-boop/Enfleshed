## Design (proposed)
- **Rush Form.** `Rush = { Mode = "Dash" | "Blink", Distance, Speed (Dash), Radius (Dash sweep), StopOnHit }`. Targeting AimDirection, horizontal aim only. Casting: Instant (no Charge/Channel at first).
  - Path plan (pure `MagicRushSpec.plan`, raycasts injected): stop short of the first wall (character-size blockcast, wall padding); walk the path in ≤ 2-stud samples and keep the last sample that is grounded (`Normal.Y >= 0.55`), within ±4 studs of the previous floor, and has clearance — so a rush toward a ledge stops at the edge instead of failing outright. Same constants as `displaceTarget`, kept in `MagicLab`. Too short (< 1 stud) → the cast does nothing, no mana spent (validated before payment, like `IMPOSSIBLE`).
  - **Dash:** server-authoritative. The server takes network ownership of the caster's root for the travel time (`Distance / Speed`, ≤ ~0.5 s), steps the root along the planned path each Heartbeat, and sweeps a capsule (`Radius`) between the previous and current position. Every newly swept target that passes the spell's target rules fires `OnImpact` once; `StopOnHit` ends the dash at the first. Arrival (or a stop) → `OnExpire`, ownership restored.
  - **Blink:** one validated teleport to the planned destination (like `correct()`): no sweep, no `OnImpact`; `OnCast` at the start point, `OnExpire` at the destination.
  - Events: `OnCast`, `OnImpact`, `OnExpire`, plus `OnDamageDealt`/`OnTargetDeath`/`OnRecast`. Payloads on Rush target what the event hands them (impact target; OnCast/OnExpire: targets inside `Radius` at that point, so "blink and burst" works).
  - `MovementService.magicRush(state, destination, duration)`: grants a one-off allowance and suspends the speed/blockcast check for that window (like `CorrectionUntil`), so the server's own move is not "corrected".
  - Rushing is blocked while Stunned/Rooted (`MagicMovementBound`), casting-locked, or during a correction.
- **Recast.** New event `OnRecast`; `Casting.MaxRecasts` 1–3 (default 1; required when OnRecast has steps).
  - `Magic.start` checks first (before the cooldown/pending gate): if the definition has OnRecast steps and the player owns a live `active` record for that SpellId with `RecastsUsed < MaxRecasts`, the press emits `OnRecast` on that record (record = `RuntimeOrigin`, so `SpellState.TriggerCount` is 1, 2, 3 for per-stage branching) and returns. No mana, no Strain, no new cooldown. Newest record wins if several exist.
  - Forms with OnRecast: those that leave an `active` record — Projectile, Field, Aura, Construct, Rush (while dashing). Not Beam/Wave (instant), not channels (a press there is already a release), not `UntilToggledOff` spells (the press is already "toggle off"; validator rejects the combination).
  - Targets/position for OnRecast: the record's current position; Field/Aura: current occupants; Projectile/Construct: targets within the form's radius; Rush: the caster.
  - Pure `MagicRecastSpec` (pick the record, can-recast, remaining) with tests; a minimum interval between recasts (`MinRecastInterval = 0.2`, provisional) stops double-press spam.
- **PvP caps.** `MaxRushDistance` 24 open / 18 ranked (provisional, against `MagicLab.MaxRushDistance = 30`); `MaxRushSpeed` not capped (distance and the sweep bound it). Recast: no separate cap (MaxRecasts ≤ 3 is the bound).
- **Companions** (summons that cast assigned spells): Rush moves its *caster*, so it is listed as unsupported for companion spells.

## Open questions / blockers

- Dash movement: server-authoritative (server owns the root during the dash; reliable, slight start delay) vs client-predicted with server validation (snappier, much more code and cheat surface). Plan: server-authoritative.
- Unsafe destination: stop at the last safe point along the path (plan) or fail the whole cast like displaceTarget?
- Recast targets/position per Form as listed above, and SelfEnhancement left out for now (enchantments live outside `active`). OK?
